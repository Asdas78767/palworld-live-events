# palworld-mod/AGENTS.md

이 파일은 `palworld-mod/` 이하 작업에만 적용하며 루트 `AGENTS.md`의 P0 규칙을 강화한다.

## 1. 지원 환경

- 공식 문서 기준 서버 측 모드는 **Windows 전용 Palworld Dedicated Server**에서만 지원되는 것으로 취급한다.
- Linux 서버용 모드 동작을 검증되지 않은 상태에서 지원한다고 주장하지 않는다.
- 서버용으로 제작된 모드만 사용한다.
- `Info.json`의 설치 규칙에 서버 지원 표시가 없으면 배포 대상에서 제외한다.

## 2. 배포 형식

- Workshop 원본은 서버 실행 파일 기준 `Mods/Workshop/<폴더>/Info.json` 구조를 따른다.
- 활성화 대상은 폴더명이 아니라 `Info.json`의 `PackageName`으로 식별한다.
- `Mods/PalModSettings.ini`에서 `bGlobalEnableMod=true`와 `ActiveModList=<PackageName>`을 사용한다.
- 모드 적용·업데이트·제거 후에는 서버 재시작이 필요하다고 가정한다.
- `-NoMods` 실행 인수가 있으면 모드가 비활성화된 상태로 판정한다.

## 3. 저장 안전 절차

모드 파일을 변경하는 자동화는 반드시 다음 사전 조건을 검사한다.

1. 후원 처리 비상 정지 활성화
2. 실행 중 작업 없음
3. `/save` 성공
4. 별도 저장 백업 완료
5. 정상 종료 완료
6. 기존 모드 목록과 버전 기록

배포 후에는 다음을 검증한다.

1. 서버 프로세스 기동
2. `/info` 응답
3. `/metrics` 응답
4. GameBridge 상태 응답
5. 읽기 전용 명령 성공
6. 허용 목록에 포함된 최소 영향 명령 1건 성공

실패하면 이전 모드 파일과 설정으로 롤백한다. 롤백 성공 전까지 후원 처리를 재개하지 않는다.

## 4. HTTP GameBridge 계약

GameBridge는 Palworld 공식 REST API와 다른 포트와 인증 체계를 사용한다.

필수 조건:

- 기본 바인딩은 `127.0.0.1`
- 인증 토큰 필수
- 요청 본문 스키마 검증
- `commandId` 필수
- 동일 `commandId` 중복 실행 금지
- 액션 허용 목록
- 아이템·팰 ID 허용 목록
- 수량·레벨·반경 상한
- 요청 타임아웃
- 구조화 실행 결과

권장 응답:

```json
{
  "commandId": "cmd_...",
  "status": "succeeded",
  "executedAt": "2026-07-17T06:00:00.000Z",
  "result": {
    "affectedCount": 1
  }
}
```

실행 결과가 불명확하면 `succeeded`를 반환하지 않는다.

## 5. 최소 액션 집합

초기 구현은 다음 순서로 진행한다.

1. `health_check`
2. `resolve_player`
3. `give_item`
4. `spawn_pal`
5. `apply_effect`

한 액션이 실제 서버에서 검증되기 전에는 다음 액션으로 범위를 확장하지 않는다.

## 6. 구현 금지

- 저장 데이터 구조를 직접 조작하여 아이템 지급
- 검증되지 않은 메모리 오프셋 하드코딩
- 클래스·함수 탐색 실패를 무시하고 성공 반환
- 게임 스레드 규칙을 확인하지 않은 비동기 객체 조작
- 무제한 소환 또는 재귀 이벤트
- 후원 메시지에서 클래스명·함수명·ID를 직접 받아 실행
- 서버 크래시 후 자동 무한 재시작
- 모드가 로드되지 않았는데 정상 상태 반환

## 7. 모드 작업 완료 조건

- Windows 전용 서버 환경에서 로드 확인
- 서버 재시작 후에도 설정 유지
- `commandId` 중복 방지 확인
- 잘못된 토큰 거부
- 허용 목록 밖 액션·ID 거부
- 최대 수량 제한 확인
- 대상 플레이어 없음 처리 확인
- 정상 저장·종료·재시작 절차 검증
- 기존 백업으로 롤백 가능 확인
- 실제 검증한 Palworld 빌드 버전 기록
